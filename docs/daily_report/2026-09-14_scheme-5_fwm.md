## 요약 판단

Scheme 5는 **실제 원자·전파 물리를 계산하는 유용한 반정량 실험 설계 도구**다.
특히 9월 11일 작업 트리에 들어온 pole–residue 리마스터는 Fast/Balanced를 Ultra와
같은 finite-Floquet 모델, 같은 4σ Maxwell 측도, 같은 64-segment readout으로 맞추면서
warm runtime을 크게 줄였다. 이것은 순수한 겉치레 최적화가 아니라, 서로 다른 tier가
서로 다른 물리를 계산하던 문제를 줄인 좋은 변경이다.

그러나 실험 reference의 경계는 여전히 명확하다.

1. **Seeded ⁸⁵Rb D1 FWM**은 detuning·온도·펌프/씨앗 세기·셀 길이·위상 부정합의
   상대 추세와 후보 운전점 탐색에는 유용하다. 기본점의 현재 Fast 결과는
   `G_s=394.8694`, `G_c=397.0960`, gain-referred diagnostic `−7.8013 dB`지만,
   문헌의 gain≈15를 재현하지 못하고 photon-flux gap과 bare-map commutator defect도
   각각 `−2.2979`, `3.3739`다. 따라서 `physical_squeezing_dB=None`이 맞다.
2. **Fast는 탐색 tier, Balanced는 수치 reference tier**로 구분해야 한다. Fast는
   기본점에서 401점 중 71점만 정확히 풀고 나머지 330점을 spline 보간한다. N_F=3/2
   검사도 정확히 푼 노드에서만 수행된다. Balanced는 401점 전부를 pole form으로
   풀어 Ultra와 거의 같은 값을 낸다.
3. **Generic SFWM / biphoton**은 복소 velocity-class 합, Autler–Townes denominator,
   vector phase matching, timing response와 detector ledger를 포함해 geometry·파형
   ordering·검출 trade-off에 유용하다. 그러나 absolute rate는 문헌 anchor이고,
   gate/filter 의미론에 아직 오류가 있어 brightness, `g²`, CAR을 독립 예측으로
   인용하면 안 된다.
4. 가장 값싼 다음 일은 full Zeeman/Langevin을 서두르는 것이 아니라 (a) Fast의
   detector-independent 적응 기준, (b) Fast의 저차수 보간 감사, (c) biphoton gate와
   rate/filter 표기, (d) `Squeezing indicator` 잔여 명칭과 예제 정리다. 원자 solve를
   늘리지 않거나 O(Nscan/Nτ) 후처리만 더해 대부분 거의 무부하로 고칠 수 있다.

## 3. 9월 9일 검토 이후의 핵심 변화

HEAD commit은 여전히 `c0c46f0`이지만, 작업 트리에는 9월 11일 작성된 대규모 미커밋

### 3.1 Fast/Balanced pole–residue 리마스터

고정 two-photon detuning에서 finite-Floquet 선형계의 velocity 의존성은
`A(t)-D S` 꼴이다. `S`의 range와 null space를 나누고 null space를 Schur 소거하면
readout은 D의 정확한 유리함수가 된다. 새 `AffineShiftSystem`은 이를 pole과 residue로
만든다 (`gabes/pole_doppler.py:1-29`, `123-194`).

- 기존 Ultra의 truncated Maxwell 노드와 가중치를 그대로 pole 합에 넣으므로, 푼 δ
  행에서는 velocity average 자체가 기존 측도와 동등하다
  (`gabes/schemes/fwm.py:2246-2266`, `2281-2297`).
- Hermiticity/adjoint identity가 정확히 성립할 때만 real finite-Floquet form을 쓰고,
  실패하면 grid solver로 돌아간다 (`gabes/schemes/fwm.py:2196-2243`, `2884-2913`).
- 모든 직접 계산 행에서 pole 값을 기존 compiled kernel의 `Δ_eff=Δ` 한 점과 비교하며,
  허용치를 넘으면 해당 행을 grid 계산으로 교체한다 (`:2258-2261`, `2300-2328`).
- Balanced는 401점을 전부 계산한다. Fast는 사용자 readout의 중점 오차로 적응 세분하고
  남은 점을 complex response spline으로 채운다 (`:2330-2374`).
- Fast/Balanced 모두 1 m/s, 4σ, 401-point, Ultra readout을 사용한다. Ultra는 기존 grid
  경로를 유지한다 (`:3349-3382`).

`analysis/fwm_lite/GATE.md`는 구현 전에 12개 운전점과 속도/개형/무결성 기준을 동결했고,
저장된 `gate_report.json`은 전 항목 PASS다. 통제된 warm 측정은 Fast 0.101 s,
Balanced 0.236 s, Ultra 약 6.2–7.5 s이며, 12개 운전점에서 Ultra 대비 최악의
S_dB tube는 Fast 0.018 dB, Balanced 0.0023 dB다
(`analysis/fwm_lite/DEVLOG.md:187-209`). 신규 테스트는 pole/grid parity, fallback,
adaptive interpolation, tier 설정, compiled/fallback parity를 직접 검사한다
(`tests/test_fwm_fast_tiers.py:14-116`).

이 변경은 **원래의 4σ Ultra 모델을 거의 그대로 더 싸게 계산하는 데 성공**했다.
기존 Fast/Balanced가 3σ와 다른 propagation readout으로 Ultra에서 최대 3.05/1.50 dB
벗어났던 것보다 훨씬 낫다 (`docs/checklist.json:1771-1787`).

### 3.2 오늘의 독립 기본점 재확인

조건: Δ=+0.9 GHz, δ=−8 MHz, 121 °C, L=12.5 mm, pump=600 mW,
seed=8 µW, angle=0.32°, η=0.8694, N_F=3 대 N_F=2.

| tier | 이번 실행 시간 | 직접 푼 δ / 표시 δ | `G_s` | `G_c` | gain-referred dB |
|---|---:|---:|---:|---:|---:|
| Fast | warm 0.11–0.13 s | 71 / 401 | 394.869399 | 397.095968 | −7.801260 |
| Balanced | 0.389 s | 401 / 401 | 394.870678 | 397.097269 | −7.801257 |
| Ultra | 13.461 s | 401 / 401×velocity grid | 394.870678 | 397.097269 | −7.800492 |

이번 직접 실행은 게이트와 다른 현재 부하/BLAS 조건이므로 절대 시간보다 비율과 출력
일치를 본다. 소스 변경 후 첫 cold-JIT Fast 호출은 16.45 s였고, disk numba cache가 생긴
새 프로세스에서는 1.097 s였다. 동결 게이트의 G1.4도 “disk cache 존재”를 전제로 한다
(`analysis/fwm_lite/GATE.md:20-23`). 따라서 UI의 `Fast (~1 s)` 표시는 cache-warm process에는
맞지만 깨끗한 첫 배포/JIT latency를 뜻하지 않는다.

세 tier 모두 Floquet status는 `CONVERGED`, claim level은 `MEAN_FIELD_DIAGNOSTIC`,
`physical_squeezing_dB`는 `None`이다. Fast와 Balanced의 동작점 차이는 매우 작지만,
문헌 gain≈15에 비하면 절대 이득은 여전히 약 26배 크다. 수치 가속은 물리 calibration을
추가하지 않는다 (`README.md:429-445`).

## 4. 실험 원자물리 관점의 평가

### 4.1 Seeded double-Λ 경로

실제 물리로 유용한 부분은 다음과 같다.

- ⁸⁵Rb D1의 F=2,3 및 F′=2,3 hyperfine-weighted 4-level double-Λ,
  trace-preserving spontaneous decay, optical/ground collisional dephasing, transit reset을
  포함한다 (`gabes/schemes/fwm.py:2640-2709`).
- pump/seed Rabi가 beam power와 1/e² waist에서 계산되고, density는 pure-⁸⁵Rb vapor
  pressure에서 온다. `C_F²/[2(2I+1)]`와 residual/lab penalty를 분리해 population을
  중복 계수하지 않는다 (`:56-122`, `2777-2790`).
- finite-seed N_F≥3 Floquet OBE와 N_F−1 비교, Doppler 평균, frequency-specific bare k,
  vacuum/geometric mismatch, 64-segment overlap·pump budget 전파를 쓴다
  (`:2732-2767`, `3013-3067`, `3089-3107`).
- small-signal field/canonical transfer, photon-flux gap, commutator defect, provenance와
  claim gate를 따로 반환한다. 물리적 covariance가 없으므로 physical squeezing을 null로
  두는 것은 올바르다 (`:3210-3268`).

이 물리는 공명 위치, branch 구조, 상대적인 knob leverage, 수치 truncation과 propagation
부호를 연구하는 데 충분히 유용하다. 그러나 absolute gain과 IDS noise에는 다음이 빠졌다.

- production은 crossing angle의 횡속도 Doppler를 원자 detuning에 넣지 않는 1-D 평균이다.
  별도 pump-only 2-D reference가 1.380 MHz Raman rms를 보이지만 finite-seed production에
  연결되지 않았다 (`README.md:263-274`; `docs/checklist.json:2548-2569`).
- pump state를 z segment마다 self-consistent하게 다시 풀지 않고, fixed susceptibility와
  post-hoc Manley–Rowe cap을 쓴다 (`gabes/schemes/fwm.py:3054-3067`, `3130-3134`).
- frequency-dependent atomic Langevin diffusion과 full covariance가 없다. gain 두 개에서
  만든 score는 physical squeezing spectrum이 아니다 (`:3137-3186`, `3215-3221`).
- inherited residual 0.74, κ, γ_transit, mode/polarization/Zeeman penalty는 독립 calibration과
  uncertainty/holdout을 갖지 않는다 (`docs/checklist.json:1875-1907`).

따라서 **상대 추세·후보점·수치 solver reference로는 유용, 절대 이득·physical squeezing·RF
bandwidth reference로는 부적합**이라는 기존 결론을 유지한다.

### 4.2 Fast의 수렴 인증 범위

새 Fast는 기본점에서 71/401점을 직접 계산하고 330점을 보간한다. `floquet_convergence`도
`scope = solved probe detunings; displayed points ... interpolated`로 정직하게 남긴다.
그러나 `full_scan_points=401`도 함께 표시되고, User Guide는 여전히 “N_F=3 전체 스캔을
N_F=2와 비교”한다고 말한다 (`docs/Userguide/GABES_User_Guide_v2.html:653-656`).

더 중요한 점은 adaptive 세분 기준이 **N_F=3의 G_s와 gain-referred score**뿐이라는 것이다
(`gabes/schemes/fwm.py:2330-2355`, `2925-2976`). 후보점을 풀 때 N_F=2 residue도 이미
계산하지만, N_F=3−N_F=2 차이의 보간 오차는 refinement criterion에 들어가지 않는다.
이는 checklist의 “10% sampled order audit은 full-scan certificate가 아니다”라는 정책
(`docs/checklist.json:6-20`)과 완료된 `fwm-floquet-convergence-gate`의 full-scan 표현
(`:1740-1766`)보다 약한 인증이다. 현재 12-case 결과와 기본점은 잘 맞지만, 좁은 order-
dependent feature를 domain 전체에서 배제하는 논리적 보증은 아니다.

권고:

- 실험 보고서용 수치에는 **Balanced 또는 Ultra**를 쓴다.
- Fast는 `adaptive/approximate` badge와 “order audit exact at solved nodes”를 더 눈에 띄게
  표시한다.
- Fast refinement에 이미 계산된 N_F=2의 readout/complex-response 오차도 포함한다. 추가
  atomic solve 없이 O(Nscan) 비교만 늘어나므로 overhead는 사실상 무시할 수 있다.

### 4.3 4σ Maxwell cutoff

Fast/Balanced가 Ultra를 잘 재현한다는 말은 **4σ에서 잘린 Ultra 측도**를 재현한다는 뜻이다.
리마스터 과정에서 untruncated Faddeeva 평균은 hot case(150 °C, Δ=0.9 GHz)의 S_dB tube를
4σ Ultra에서 최대 0.112 dB 이동시켰다. F′ 공명 무리가 3.4–5σ에 있어 물리적으로 존재하는
고속 원자를 cutoff가 자르기 때문이다 (`analysis/fwm_lite/DEVLOG.md:99-109`).

기존 `fwm-ultra-maxwell-cutoff-scope`는 이를 `needs_decision`으로 정확히 기록한다
(`docs/checklist.json:1790-1805`). 계산비용 평가는 다음과 같다.

- 현재 4σ behavior를 보존: 현 pole `discrete_mean()` 그대로, 추가비용 0.
- pole tier를 continuous Maxwell로 변경: `gaussian_mean()`가 이미 Faddeeva 닫힌형으로
  구현되어 있어 (`gabes/pole_doppler.py:97-120`) 비용은 현 pole 합과 같은 작은 행렬
  후처리 수준이다. 물리는 더 자연스럽지만 숫자와 Ultra baseline은 바뀐다.
- Ultra를 6–8σ grid reference로 확장: 1 m/s 간격이면 velocity class 수와 시간이 약
  1.5–2배 늘 수 있다. 기본 interactive tier가 아니라 offline 검증 기준으로 적합하다.

즉 이 개선은 pole tier에서는 거의 무료지만, **기존 4σ model behavior를 보존하는 순수
최적화가 아니라 Maxwell 측도 정의를 고치는 physics/numerics 결정**이다.

## 5. Source/detection 층분리의 새 세부 문제

`detection_eff_pct`, hidden `loss_pct`, `qe_pct`는 `ParamSpec.recompute=True` 기본값을
그대로 쓴다 (`gabes/schemes/base.py:44-56`; `gabes/schemes/fwm.py:3515-3530`). UI cache는
모든 recompute knob를 heavy `compute()` key에 넣는다 (`streamlit_app.py:637-642`,
`1920-1928`). 기존 `fwm-gain-only-trust-boundary`도 detector parameter를 source cache에서
빼라고 요구한다 (`docs/checklist.json:1625-1663`).

리마스터 전에는 η가 atomic transfer를 바꾸지 않는데도 재계산만 느린 문제였다. 새 Fast에는
추가로 **η가 adaptive node 선택을 바꾸어 보간된 source 배열까지 바꾸는 문제**가 생겼다.
score가 `balanced_twin_beam_noise(..., eta, eta)`를 직접 쓰기 때문이다
(`gabes/schemes/fwm.py:2971-2976`). 오늘의 기본점에서:

| η | Fast 직접 노드 | Balanced 대비 max relative `G_s` 오차 |
|---:|---:|---:|
| 0.00 | 55 | 0.1683% |
| 0.10 | 59 | 0.1685% |
| 0.50 | 61 | 0.1687% |
| 0.8694 | 71 | 0.0505% |
| 1.00 | 75 | 0.0505% |

η=0.8694→0.5만 바꾸면 exact atomic source는 같아야 하지만 Fast의 `G_s`, `G_c`,
small-signal gains와 두 transfer 배열이 bitwise 달라졌고 `G_s` 최대 절대차는 0.396이었다.
재계산은 warm 약 0.116 s, 이미 계산한 gain array의 η remap은 median 18 µs여서 약 6,400배
차이다.

해결은 다음과 같이 하면 물리를 보존하며 거의 무부하다.

1. pole/source refinement는 detector-independent `log G_s`, complex response, N_F order gap과
   고정된 canonical reference score로 결정한다. η 범위 전체에서 error gate를 돌린다.
2. source raw에는 transfer/gain과 interpolation provenance만 저장한다.
3. η/loss/QE는 `_seeded_observables()`의 O(Nscan) detector remap에서만 적용하고
   `recompute=False`로 만든다.

Balanced는 이미 401점을 전부 풀기 때문에 node-choice 문제가 없고 가장 쉽게 분리할 수 있다.
Fast는 위의 고정 node policy를 먼저 정해야 현재 근사 허용치를 보존할 수 있다.

## 6. Generic SFWM / biphoton 재확인

### 6.1 실제로 구현된 유용한 물리

- ⁸⁷Rb telecom cascade, ¹³³Cs 두 cascade channel, generic diamond를 wavelength/direction/
  decay topology로 만든다 (`gabes/schemes/fwm.py:768-801`, `1025-1173`).
- reduced waveform은 velocity-class complex amplitude를 coherent sum하고 Ω_c²
  Autler–Townes term, 자연붕괴 envelope, vector phase-matching amplitude를 포함한다
  (`:1291-1370`). velocity step을 자동 반감해 waveform width를 수렴시킨다
  (`:1375-1455`).
- source/detected FWHM을 timing convolution 전후로 분리하며 filter, efficiencies,
  background, coincidence ledger를 후처리한다 (`gabes/observables.py:285-364`).

기본 ⁸⁷Rb telecom reduced source 재확인:

| 항목 | 값 |
|---|---:|
| raw reference-anchored pair rate | 380.000 cps |
| waveform source bandwidth | 914.760915 MHz |
| 300-MHz scalar filter transmission | 0.3279545 |
| filter 후 pair rate | 124.622727 cps |
| intrinsic / detected FWHM | 0.172599 / 0.496519 ns |
| velocity step / status | 0.179153 m/s / converged |
| OD / vector phase match | 112.0 / 1.0 |

### 6.2 기존에 남아 있는 gate와 bandwidth 오류

`biphoton_stats()`는 filter를 단순 bandwidth ratio로 rate에 곱하고, coincidence window는
accidental에만 곱한다. true coincidence는 window와 무관하다
(`gabes/observables.py:310-327`). 기본 파형에서:

| gate window | true coincidence | CAR |
|---:|---:|---:|
| 0.01 ns | 1.246227 cps | 30,771.0 |
| 0.05 ns | 1.246227 cps | 6,154.2 |
| 1.00 ns | 1.246227 cps | 307.71 |

window→0에서 true count가 0으로 가지 않고 CAR가 발산한다. 기존 테스트는 background와
window를 동시에 바꾼 뒤 CAR가 감소하는지만 검사해 이 결함을 잡지 못한다
(`tests/test_fwm_generic.py:128-140`). normalized detected delay PDF의 gate 적분을 true
coincidence에 곱히면 되며 481-point O(Nτ) 후처리라 source physics와 runtime을 사실상
바꾸지 않는다.

또한 literature table의 `Bandwidth setting` 행은 계산 source bandwidth 914.8 MHz가
아니라 사용자가 넣은 filter 300 MHz를 reference 300 MHz와 비교해 `PASS`를 준다
(`gabes/schemes/fwm.py:4321-4328`). 입력값 자기비교이므로 `configured/by construction`으로
옮기고, computed source bandwidth는 별도 `predicted (approx)` 행으로 보여야 한다.

### 6.3 새로 확인한 rate/filter 표의 모순

같은 table의 `Pair rate / pump`는 `stats['pair_rate_cps']`, 즉 **filter 후 rate**를 pump로
나눈다 (`gabes/schemes/fwm.py:4291-4297`; `gabes/observables.py:310-315`). 기본값은
12,462 cps/mW로 표시되는데 reference는 38,000 cps/mW이고 verdict는 `by construction`이다.
이는 실험 plane을 섞은 모순이다.

- source row: raw anchored 380 cps / 0.01 mW = 38,000 cps/mW, `by construction`.
- detected/filter row: 124.623 cps / 0.01 mW = 12,462 cps/mW, filter throughput 0.328을
  명시하고 calibration PASS를 주지 않는다.

이 분리는 O(1) 표기 변경이며 `biphoton-source-trust-boundary`의 per-output provenance
요구와 정확히 맞는다 (`docs/checklist.json:1127-1157`).

## 8. 순수 코드 최적화 후보

### 8.1 detector/source cache 분리

위 5절의 고정 adaptive policy 뒤 η/loss/QE를 O(Nscan) readout으로 옮기면 warm 기본점에서
약 0.12 s→18 µs 수준이다. 원자 transfer를 바꾸지 않고 UI latency와 cache hit를 개선한다.
현재 가장 큰 남은 exact optimization이다.

### 8.2 full-scan extra view와 분석 scanner에 pole engine 재사용

`pole-residue-doppler-reuse`는 `ready`다 (`docs/checklist.json:1808-1822`). 현재 wide
two-branch extra view는 여전히 옛 3σ/4 m/s 또는 3σ/2 m/s grid 설정을 사용한다
(`gabes/schemes/fwm.py:3372-3379`, `4394-4417`). `analysis/squeezing`의 수동 scanner도
velocity마다 큰 χ table을 만든다. affine 조건, branch frame, 동일 측도와 row guard를
확인한 뒤 pole form을 쓰면 physics behavior를 tolerance 내 보존하면서 큰 speedup과 메모리
절감을 기대할 수 있다. 다만 wide + branch는 pump-only reference에서 unsupported인 + branch와
혼동하지 않도록 finite-seed 모델 범위를 그대로 표기해야 한다.

### 8.3 biphoton 1-D angle trace vectorization

figure 경로는 181개 angle을 Python loop로 `phase_mismatch_vector()`에 넣는다
(`gabes/schemes/fwm.py:4086-4098`). 이미 있는 vector grid helper (`:941-967`)를 1×181로
재사용할 수 있다. 오늘 측정은 536.85→43.30 µs, 12.4×였고 Δk 최대 차는
`1.16×10⁻¹⁰ m⁻¹`로 연산 순서 수준이다. 절대 절감은 약 0.49 ms/render로 작으므로 P3 정리다.

### 8.4 cold-JIT latency를 측정값에서 분리

새 pole tier의 warm speed는 훌륭하지만 clean source/JIT 첫 호출은 이번 환경에서 16.45 s였다.
disk cache 존재 시 새 process 1.10 s였다. prewarm 또는 배포 빌드 cache가 안정적으로 가능한지
검토하고, 불가능하면 UI의 timing help에 warm/cold 조건을 나눈다. 물리와 출력은 바뀌지 않는다.

1. **User Guide는 pole remaster 이전 상태다.** FWM 시간을 `~1–14 s`라 하고 N_F=3/2를

   Fast의 71/401 exact-node scope와 pole/4σ measure를 넣고 PNG도 다시 생성해야 한다.
2. **사용자 표면에 `Squeezing indicator`가 남아 있다.** stored mode key는 이미
   `Gain diagnostic`이지만 UI label은 `Squeezing`, plot/hero도 `Squeezing indicator`다
   (`gabes/schemes/fwm.py:673-679`, `3896-3917`). `physical squeezing unavailable` 보조문은
   좋지만, P1 trust item의 ambiguous surface 은퇴는 완료되지 않았다.
3. **대표 Δ–T scanner는 옛 physics path다.** `scan_squeezing_delta_T.py`는 physical
   squeezing을 “maximize”한다고 쓰고 (`:1-28`), 3σ/5 m/s와 81점 grid를 쓴다 (`:60-66`,
   `101-120`). `chi_matrix_table()`의 기본 `n_f=1`을 명시 없이 사용한다
   (`gabes/schemes/fwm.py:2112-2117`)며, current Ultra phase/depletion/Option-A readout이 아닌
   단순 gain path를 직접 조립한다 (`analysis/squeezing/scan_squeezing_delta_T.py:124-146`).

   `p_F`를 여전히 말한다 (`:14-15`, `46-52`, `136-142`). historical fixture로 명시하거나
   current `FWMScheme.compute`/pole API와 N_F=3/2 gate를 쓰도록 고쳐야 한다.
4. **Biphoton detector test가 부족하다.** 작은 window가 true coincidence capture를 줄이고
   source/filter/detected rate plane이 섞이지 않는 단일변수 테스트가 필요하다. 현재 test는
   background와 window를 동시에 바꾼다 (`tests/test_fwm_generic.py:128-140`).
5. **Fast detector-independence test가 없다.** Balanced source와 비교해 η 변화가 atomic
   transfer/source interpolation을 바꾸지 않는지, 그리고 η 전체 범위에서 displayed score
   tolerance를 지키는지 고정해야 한다.

## 11. 실험 연구자용 최종 권고

현재 Scheme 5를 다음처럼 사용한다.

- **Fast**: detuning/temperature/power/geometry 탐색과 후보점 찾기. adaptive/interpolated
  결과이며 order audit가 exact-node 범위임을 기록한다.
- **Balanced**: 현재 1-D finite-seed/4σ 모델 안에서의 수치 reference와 보고용 곡선.
- **Ultra**: grid cross-check와 cutoff 연구. 물리적 진실의 별도 tier로 해석하지 않는다.
- **Biphoton**: waveform ordering, phase-matching geometry, timing/filter/background 설계.

다음 용도에는 아직 쓰지 않는다.

- absolute seeded gain, physical IDS squeezing, RF squeezing bandwidth의 예측/fit reference.
- TPD scan 폭이나 atomic pole 폭을 RF bandwidth로 해석.
- reduced biphoton의 absolute brightness, `g²`, CAR, ns 폭을 독립 validation으로 인용.
- filter 설정 300 MHz가 문헌값과 같다는 이유로 계산 source bandwidth를 검증했다고 주장.

권장 실행 순서:

1. Fast refinement를 detector-independent로 만들고 N_F=2 보간 오차도 refinement에 넣는다.
2. η/loss/QE source-cache 분리와 `Squeezing indicator` 잔여 표면을 정리한다.
3. biphoton gate capture, raw/filtered rate plane, computed/configured bandwidth를 분리한다.
4. User Guide와 `scan_squeezing_delta_T.py`를 현재 pole/N_F/trust 경계에 맞춘다.
5. 4σ Maxwell measure를 유지할지 continuous Gaussian으로 바꿀지 결정하고 12-case gate를
   다시 실행한다.
6. 그 뒤에 opt-in finite-seed 2-D와 self-consistent z propagation을 검증한다.
7. microscopic Langevin/full covariance/RF spectrum과 held-out 실험 검증은 별도 연구 단계로
   유지한다.

요약하면, 새 pole–residue 엔진 덕분에 Scheme 5의 **수치적 reference 품질과 상호작용 속도는
크게 좋아졌다.** 하지만 이는 현재 1-D·4σ·mean-field 모델을 빠르게 푸는 성과이지,
absolute gain·physical squeezing·biphoton count model의 실험 검증은 아니다. 지금 가장
효율적인 개선은 더 큰 Hamiltonian보다 이미 드러난 layer/measure/claim 경계를 닫는 것이다.
