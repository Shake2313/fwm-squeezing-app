# Grand Challenge Lean 사용 지침

현행 판본: **v0.1 · 2026-10-28**  
상태: **도입 준비 완료 — Lean을 선택한 GC 작업의 개선 가능한 기본 방식**. 모든 GC 작업에 Lean을 요구하거나 새 완료 관문을 만드는 문서가 아니다.

## 사용자 방향과 이 문서의 역할

2026-10-28 사용자 요청: 시범 로그를 토대로 도입을 준비하고, AI 에이전트 모델의 발전을 감안하여 규약을 고정하지 않는다. 유의미하고 일관적인 방식으로 사용하되, 개선안이나 동일한 결과를 내는 더 나은 방법을 발견하면 사용자에게 제안하고, 규약을 수정한 후 문서 하단에 수정 내역을 남긴다.

이 문서는 그 요청을 구체화한 현행 작업 지침이다. 아래 세부 절차는 ⟦AI⟧ 구현 제안이며 실제 사용 경험에 따라 바꿀 수 있다. 최신 사용자 지시와 현재 작업의 목적을 우선한다. 예전 절차를 준수했다는 사실보다 정확한 명제·근거와 유용한 결과가 중요하다.

## ⟦AI⟧ 출발 근거

[단회 시범 보고서](lean_pilot_2026_10_28/README.md)와 [실행 기록](lean_pilot_2026_10_28/run/receipt.json)에 근거한다.
Lean 4.35.0의 core/Std로 유리수 scalar 공분산 채널의 일반 항등식 6개와 정확한 사례·반례 7개를 검사했다.
13개 정리는 표준 공리만 사용했고, 두 잘못된 잡음 등식의 증명 시도가 거부됐다. 준비된 환경의 전체 검증은 그 실행에서 약 5.2초였다.

이 결과는 작은 대수 연결의 유용성을 보여준다. 실수/복소수 행렬, 일반 완전양성(CP), 원자→광장 미시 연결, Python 구현과의 동등성은 아직 이 시범으로 검증하지 않았다.
13개·2개라는 수나 실행 시간은 향후 작업의 목표치·보장값이 아니다. 시범 당시의 도입 보류와 로그는 역사적 사실로 보존하고, 현재 운영 방향은 이 문서를 참조한다.

## ⟦AI⟧ 적용 대상을 고르는 기본 방식

반복해서 쓰는 유도, 표현 사이의 연결, 가정 누락 위험이 큰 식부터 비용 대비 가치를 살핀다.
예를 들면 공분산 채널 합성, 정규화 변환, 유한 차원 보존 성질, 명시한 관계의 동치·순서 성질이다.
현재 GC 질문에 도움이 되는 작은 명제 하나로 시작하는 방식이 합리적이다.

형식화 비용이 현재 문제에 비해 크면 독립 유도나 적절한 수치 검증을 먼저 사용할 수 있다. 통상적인 UI·문서 작업이나 이미 같은 상태에서 검증된 증명에 Lean 실행을 붙일 이유는 적다.
매 턴 형식적인 미사용 사유를 작성할 필요는 없다. 방법 선택이 결과 해석이나 다음 작업에 영향을 줄 때 짧게 설명한다.
AI 모델의 발전으로 더 큰 범위를 다룰 수 있게 되면 이 판단도 새 근거로 갱신한다.

## ⟦AI⟧ 현재의 작업 흐름

1. **명제를 물리적 의미와 함께 적는다.** 출처의 식, 대상 수 체계·차원, 기호·단위·정규화, 가정, 원하는 결론을 짧게 연결한다. GC 코드의 어떤 양과 대응하는지도 확인한다.
2. **작은 증명을 구성한다.** 기존 정리·라이브러리를 먼저 살피고 필요한 정의와 보조정리를 작성한다. 결론을 가정에 넣거나 가정이 모순되어 자동으로 참이 되는 경우를 검토한다. 명시한 가정이 실제 모델에서 성립하는지는 별도의 물리 질문이다.
3. **실제 검사와 의미 검토를 함께 한다.** 선택한 도구로 증명을 검사하고, 검사한 명제가 원래 의도한 명제인지 읽는다. 필요하면 극한·정확한 사례·반례나 독립 검토를 더한다. 실패 대조는 import 오류 같은 환경 실패와 수학적 거부를 구분한다.
4. **주장에 맞는 근거를 남긴다.** 명제/소스, 도구·의존성 판본, 재현 명령, 실제 결과, 가정·공리/신뢰 범위, 관련 원문/코드 연결을 복구 가능하게 기록한다. 근거가 이미 있으면 링크로 재사용한다.
5. **효용을 평가한다.** 잡은 오류, 닫힌 수학적 연결, 재사용 가능성, 작성·검사 비용을 보고한다. 형식화한 식의 증명과 실험 검증 또는 구현 검증의 범위를 각각 설명한다.

단계 수나 순서는 고정된 의식이 아니다. 목표와 근거를 보존하면서 단계를 합치거나 다른 검증 경로를 사용할 수 있다.

## ⟦AI⟧ 도구·검증의 현행 기본값

| 항목 | 출발 방식 | 개선 가능한 지점 |
|---|---|---|
| 프로젝트 | production과 분리된 작은 Lean 프로젝트 | 재사용이 늘면 공통 라이브러리·폴더 구조 검토 |
| 도구 | 시범의 Lean 4.35.0 core/Std를 재현 기준으로 사용 | 새 Lean·Mathlib·증명 보조 도구가 더 적합하면 비교 후 변경 |
| 증명 작성 | 읽을 수 있는 정의와 theorem, 목적에 맞는 tactic | AI 모델·tactic·보조정리 분해·검색 방식 변경 |
| 신뢰 확인 | 실제 빌드와 주요 정리의 공리 의존성 확인 | 동등한 정보를 주는 검증 도구나 기록 형식으로 개선 |
| 회귀 확인 | 바뀐 명제와 의존하는 증명 중심 | 관련 근거가 그대로면 재사용; 영향이 넓어질 때 확대 |

시범은 `propext`, `Classical.choice`, `Quot.sound`만 의존했다.
미완성 `sorry`, 추가 공리, native 평가 등으로 신뢰 범위가 달라지면 그 차이를 결과에 드러낸다.
“더 최신 AI가 작성했다”는 이유만으로 증명 근거가 대체되지는 않는다.
동일한 보증을 제공하는 검사 자동화는 유용한 개선 후보이고, 보증 수준 자체의 변경은 별도 선택이다.

## ⟦AI⟧ 개선 제안 → 개정 → 하단 이력

사용 중 더 명료하고 안정적이거나 효율적인 방법을 발견하면, 에이전트는 사용자에게 **바꿀 점·이유·예상 이득·동등성을 확인할 방법**을 짧게 제안한다.
제안은 문서 개정 전에 알리고, 사용자 의견이 오면 반영한다.

현재 맡긴 작업 범위 안에서 목표와 보증을 유지하는 가역적인 방법 개선은 제안 후 검증·개정·보고까지 진행할 수 있다.
이 지침 자체가 매번 추가 허가를 받으라는 절차를 만들지는 않는다.
가정·결론·허용 오차·검증 신뢰도·실험 판정 기준을 바꾸거나 위임 범위를 넘어서는 선택은 동일 결과를 내는 개선과 구분해서 사용자에게 설명한다. 필요한 사용자 결정은 그 변경 내용에 따라 판단한다.

**동일한 결과인지 확인할 때의 비교 기준:**

- 원래 명제의 의미와 정의가 같거나, 새 표현과의 동등성이 설명·검증되는가?
- 가정·적용 영역·물리적 정규화가 유지되는가? 좁아진 영역이나 강해진 가정은 있는가?
- 증명된 결론과 공리·신뢰 범위, 필요한 회귀/반례 검사가 유지되는가?
- 동일한 소수의 숫자만 재현한 것은 아닌가? 예를 들어 모든 유리수에 대한 정리를 몇 개 값의 테스트로 대체하면 근거가 달라진다.
- 시간·작성 부담·가독성·재사용성 중 무엇이 실제로 좋아졌는가?

검증 결과가 개선을 지지하면 **이 문서의 해당 본문을 갱신하고, 맨 아래 수정 이력에 날짜·바뀐 내용·이유·근거·적용 상태를 추가**한다.
바뀐 규약을 가리키는 진입 문서나 현행 상태가 있으면 함께 맞춘다.
시범 로그와 과거 증거는 당시 판본의 기록으로 남긴다. 보류한 제안은 미적용으로 보고하며 실제 개정으로 기록하지 않는다.
개별 증명 파일의 모든 편집을 규약 이력에 쌓기보다는, 앞으로의 작업 방식을 바꾸는 변경을 남긴다.

## ⟦AI⟧ 기존 시범 활용과 다음 적용 준비

[시범 프로젝트](../../analysis/grand_challenge/lean_pilot/README.md)는 재현·학습용 기준이다.
기존 runner는 **그 시범의 13개 정리와 두 실패 대조에 맞춘 검사기**이므로 다른 GC 명제에 그대로 적용하는 범용 검사기로 취급하지 않는다.
새 작업은 실제 정리 목록·필요한 검사에 맞게 구성하고, 통과한 근거를 연결한다.
시범의 기본 출력 경로는 원래 기록과 겹치므로 재실행할 때 새 `-OutputDir`를 지정한다.

저장소 루트 PowerShell에서 기존 사례를 재현하는 예:

```powershell
.\analysis\grand_challenge\lean_pilot\setup.ps1
.\analysis\grand_challenge\lean_pilot\run_pilot.ps1 -OutputDir "$env:TEMP\gabes-lean-review-$(Get-Date -Format yyyyMMdd-HHmmss)"
```

setup은 임시 폴더의 휴대형 설치를 복원할 수 있다. 장기 사용할 설치 경로는 `-InstallRoot`, 실행할 도구 경로는 `-LeanBin`으로 지정할 수 있다.
4.35.0은 이 시범의 재현 기준이며 향후 모든 작업을 고정하는 판본이 아니다.

다음 실제 적용의 후보는 **GC 광장/공분산 유도의 유한 차원 채널 합성식 하나**다.
시작할 때 기존 원문 식과 코드 위치, 명제·가정, 예상 효용, 필요한 라이브러리, 판단할 결과를 짧게 정리하면 된다.
실수행렬·CP 확장은 별도 범위로 평가한다. 이번 준비 작업에서는 그 증명을 착수하거나 자동 실행을 예약하지 않았다.
