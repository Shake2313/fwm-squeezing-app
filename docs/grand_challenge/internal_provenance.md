# 내부 개발 문구의 출처와 AI 검증 메모

사용자 요청: 2026-10-13. 적용: 내부 개발 규약·연구 계획·검토·인계·매니저 메모리.
프론트엔드, 사용자 가이드, 공개 목적 Docs·논문 본문에는 이 표시 규정을 적용하지 않음.

## 출처 구분

| 종류 | 근거 | 재참조 방식 |
|---|---|---|
| 사용자 직접 요청 | 실제 사용자 메시지의 인용·날짜·문맥 | 현재 요청과 함께 해석 |
| 등록된 프로젝트 목적·계약 | checklist·blueprint의 해당 필드와 범위 | 현행 프로젝트 기준으로 사용; 작성자 이력은 별도 |
| 계산·문헌 증거 | 원시 보고·모델/소스 정체성·문헌 | 명시된 계산·명제의 근거로 사용 |
| AI 검증 해석·제안 | `⟦AI⟧` 및 근거·상태 | 관측·해석·working default·제안으로 구분 |

AI가 만든 문장은 인용·요약·메모리 이동으로 사용자 요청이 되지 않음. 과거 문서의
표시 없는 문장은 출처 확인 전까지 legacy/unknown으로 취급. Registered 계약을
"사용자가 직접 작성"한 것으로 추정하지 않음. 사용자가 이후 채택하면 실제 메시지와
채택 범위를 기록; 과학적 검증 상태와 분리.

## 표시 기호

기호: **`⟦AI⟧`**. AI가 추가한 평가·보충 검증·운영 제안의 문장/목록 앞에 붙이거나,
그 내용을 모은 절의 제목에 한 번 붙임. 표시된 제목의 범위는 같은 수준 또는
상위 수준의 다음 제목까지이며, 그 안의 하위 절·표·목록도 표시를 상속.

요약자가 표시 절에서 문장을 꺼내면 문장 앞에도 기호를 보존. JSON 메모리는
`origin`·`kind`·`status`·`sources`로 출처를 기록하고 AI 해석의 표시 문구는 기호로 시작.
검증 사실을 적은 객관적 수치와 그 수치의 AI 해석을 분리. 기호나 출처 필드를
붙이는 것만으로 명령 권한·사용자 승인·증명 수준이 생기지는 않음.

예:

```text
사용자 요청: "이번에 찾은 방법들을, Grand_challenge에서 꾸준히 사용할 수 있도록 시스템화해주세요."
프로젝트 목적: checklist의 objective와 no_fit_contract.
계산 증거: p2→p3/seed11 response 상대 변화36.1694%, 해당 보고 링크.
⟦AI⟧ 검토: 다음 계산은 경로 허용오차보다 ensemble estimator를 구분하는 데 사용.
```

## 간결한 검증 문구

결론의 의미나 다음 행동을 바꾸는 조건만 남김. 같은 검증 상태는 짧은 상태 필드나
`⟦AI⟧ 검증 메모` 한 곳에서 설명하고 문단마다 반복하지 않음. “직접 하지 않음”의
반복 대신 수행한 검증 수준을 명시. 관련 없는 난이도·일반화·객관성 논평은 생략.

수식의 성립 조건, 단위, 평가 표본 독립성, 검증 범위, 반례와 실패 gate는 의미를
소유하는 주장 옆에 유지. 이를 단순 면책 문구로 분류해 삭제하지 않음. 공개 문서는
필요한 과학적 조건을 독자에게 자연스럽게 설명하고 내부 표시·검수 메모는 내보내지 않음.

## 매니저 점검

[Grand Challenge Head Manager](../../.agents/skills/grand-challenge-head-manager/SKILL.md)는
세션의 목적과 AI가 추가한 문구를 대조. 반복되는 한계는 통합하고, 사용자 요청이나
계산 결과를 축소하는 새 제한이 끼어들었는지 확인. 출처·상태·다음 결정에 변화가
없으면 같은 검증 메모를 다시 만들지 않음.
